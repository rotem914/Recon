Date: 2026-09-13. Scope: the whole repository at commit `0ce921f`, code and plan, read in
full: `host/src/*`, `editor/*`, `project-os/*`, `CLAUDE.md`, `Installation.md`. Nothing was

`cargo clippy --all-targets -- -D warnings` clean, 14 unit tests pass. The 33 editor checks
and the self test were last run on 2026-09-11 on this same commit and are taken as they were

Verdict, 2026-09-13: **fix all**, and the recommended order stands. Status per finding

---

## Direction

**The direction is right, and the foundation is unusually well proven for four steps.**
Four Stage 0 steps are closed on evidence rather than on a feeling: the capture coordinates
are byte-exact at both corners of the display, the process boundary was measured instead of
quoted, the editor lays text out in image pixels so zoom cannot re-wrap a line, and the
hidden window's first frame was checked on the screen instead of asked of the page. The
architecture split, host owns the pixels and the web view owns the text, is sound and the
measurement backed it.

**What is not yet true: the four pieces have never run as one thing.** The hotkey path ends
by writing a PNG beside the executable. The editor is built only by its own diagnostic
runtime (`--editor-check`, `--editor-demo`) and never by the product path. No capture has
ever reached the editor. Until they are wired, the plan's second latency interval, selection
to a usable editor, cannot be measured, and the two open editor findings (F43, F44) are being
judged on a diagnostic window rather than the real one.

**Every number in the plan is a debug-build number, and the plan does not say so.** The
freeze at 166 ms includes a per-pixel byte-order loop compiled without optimisation. The
fit view at 1.1 s (F43) was measured the same way. Decisions are already being drawn from
those figures. Re-measure in a release build before any of them drives a design.

**The step order should change before S0.5.** S0.5 as written cannot close: its end-to-end
tests (animation frame through save, restart and export; orientation and colour through the
same cycle; SVG raster size through reopen and export) need the export (S0.6) and the store
(S1.8), which do not exist. S0.6's export route is also the single largest architectural
risk still open, because if the serialized layer cannot be read back, the composer moves
in-process and the editor changes shape. It is also cheap to probe: a day, against a week
for nine formats.

Recommended order:

1. Wire capture to editor end to end, on the product path (T1).
2. Spike the S0.6 export route: serialize, draw, read back, composite one capture (T5).
3. Fix the fit view (T2), then re-measure everything in release (T3).
4. S0.5 decode, with its cycle legs carried to S0.6 and S1.8 explicitly (T4).

```
T2 · The fit view costs a second, and nothing is scheduled to fix it (F43)
Where:   host/src/editor.rs:452 (full-region Triangle resample on every view change)
Problem: Every zoom, pan or resize resamples the whole visible region from the full
         image. Opening a 4K image is a 1.1 s wait for the first thing anyone sees, and
         the viewer's core promise is opening quickly. The finding is open in the plan
         with no step owning it.
Fix:     Build a pyramid once per image in the host (half, quarter, eighth, by 2x2 box
         average, cheap and exact at powers of two). Serve a region from the nearest
         level at or above the requested scale, then resample the small remainder.
         The 1:1 path stays as it is. Assign it to the step that wires the editor (T1)
         or to S0.5, where opening a file first shows a fit view.
Verify:  The region log for a fit view of the 3840x2160 probe reads under 50 ms in a
         release build, and the 33 editor checks still pass, including the checkerboard
         crispness at 1:1 after a fit view.
Status:  [x] done 2026-09-13; 44 to 51 ms, and the cause was a generic resample compiled
         unoptimised in the host crate, now in host/pixels
```

```
T6 · A note typed on two lines probably loses its line break when editing ends
Where:   editor/index.html:411 (commitEditing reads textContent)
Problem: Enter inside a Chromium contenteditable inserts a block, not a newline
         character. textContent joins blocks with nothing between them, so committing a
         two-line note yields one run of text, and layoutScene then writes that back
         into the bubble. The typed line break is gone silently. The check "typed text
         survives the commit" sets textContent directly, so it cannot see this.
         Inferred from Chromium's contenteditable behaviour, not reproduced here.
Fix:     Read innerText (which turns block breaks into newlines), or intercept Enter and
         insert a text newline, since .t already renders pre-wrap. Add a check that uses
         execCommand('insertParagraph') between two insertText calls and asserts the
         committed text contains a newline.
Verify:  In --editor-demo, click, type "one", press Enter, type "two", press Esc. Two
         lines stay two lines. Blocking if this reproduces, because it is silent loss of
         what the user typed.
Status:  [x] done 2026-09-13; Enter inserts a newline character, the commit reads innerText,
         paste is plain text, and three checks cover it
```

```
T8 · Region requests pile up with no cancellation
Where:   host/src/main.rs:207 (a thread per request), editor/index.html:170 (the page
         drops late answers by ticket)
Problem: Holding an arrow key sends a region request per keypress. The host spawns a
         thread and a full resample for each, and the page discards the late ones. The
         work is still done: ten keypresses on a 4K image is ten concurrent resamples
         and ten 3.5 MB buffers. The page is correct; the host has no "latest wins".
Fix:     One resample worker with a single-slot mailbox: a new request replaces the
         pending one, and only the newest is served. With T2 in place each job is small,
         but the shape should still be one worker.
Verify:  Hold the right arrow for two seconds on the 4K probe; the region log shows one
         resample in flight at a time and the last one painted.
Status:  [x] done 2026-09-13; one worker, one slot, a replaced request answers 409
```

## Things looked at and found sound

Listed so the next reader does not re-review them.

- `capture/coords.rs`: i64 arithmetic, refuses rather than clamps, tested against negative
  origins. This is the right shape and the tests are real.
- `overlay.rs`: own thread, own pump, selection on the frozen image, drag clamped to its
  display, dim in four rectangles with a coverage test. Teardown releases every handle.
- The `Selecting` guard releases on drop, so a panicking selection does not kill the hotkey.
- `editor/index.html`: two coordinate spaces only, one transform for zoom, layout in image
  pixels, late region answers dropped by ticket, the ratio measured against the host instead
  of believed from devicePixelRatio, centring shared by canvas and callout layer.
- Text direction: three explicit modes resolved once per bubble from the first strong
  character, which is what the plan's F36 fix asked for.
- The checks: each names what it compares and what would turn it red, after the three false
  negatives were found and fixed. The first-frame check reads the screen, not the page.
- The process docs: History carries the rollback commit and the review result per row, the
  Decisions entries have all four parts, one plan file, Mistakes promoted on the second slip.
